# Per-section vault sourcing (pointers, not conventions)

This file grows empirically, one confirmed finding at a time, every time this skill is
actually run end-to-end on a deal. Add to it after each run rather than trying to
anticipate gaps in advance — see the Exploration mandate in SKILL.md for why a
routing table can only ever cover what someone already thought to look for.

Read `SKILL.md`'s "Sourcing discipline vs. analytical judgment" section before using
this table: the tool names and verification steps below apply to every deal; the
specific figures, counts, and conclusions quoted below (drawn from testing against
a reference deal, unless a section notes a different deal) are worked examples,
not a template to expect on a different deal.

---

## RENDER FORMAT per section (read this FIRST, check it LAST)

This is the structural format each section MUST render in, pulled out of the sourcing
prose below on purpose: format kept getting lost inside the dense tile-routing cells and
rendered as prose when a table was required (caught on live builds — two builds
both rendered §9 and §10 as prose cards instead of tables). Treat this block as
a contract. It is separable from sourcing so it can be verified mechanically at the end
(see "After producing the memo → render-format check" in SKILL.md). If a section's
declared format here says table, a prose write-up of that section is a defect, however
well-written.

| # | Section | RENDER AS |
|---|---------|-----------|
| 1 | Exec Summary & Credit View | prose + two tables (compact deal-terms table, and the 8-dimension Summary Scorecard table) |
| 2 | Transaction & Cap Structure | tight prose + three tables (Sources & Uses, Pro Forma Cap, and **Key Terms as a table — not a paragraph**) |
| 3 | Sponsor & Management | prose + management table (Name / Title / Tenure / Experience) |
| 4 | Business Overview | prose + segment table + customer-concentration table |
| 5 | Industry & Market Position | prose + barriers-to-entry table |
| 6 | Financial Performance | prose + historical table + EBITDA-bridge table (waterfall walk) |
| 7 | Balance Sheet, Liquidity & Collateral | prose + forward credit-stats table + capital-structure/recovery table |
| 8 | AI Review | prose (length tracks disclosure; no required table) |
| 9 | Credit Strengths | **TABLE** — one row per merit: Number / Title / Stat Line / Body / Credit Implication / Peer Benchmark (no Severity column) |
| 10 | Key Risks & Mitigants | **TABLE** — one row per risk: Number / Severity / Title / Body / Mitigant / Peer Benchmark |
| 11 | Valuation Benchmarking | prose + peer/comp table (or the suggestions-only variant when no confirmed comps) |
| 12 | Open Diligence Items | ranked list (≤10 lines); no callout boxes |
| 13 | Recommendation | prose only (restatement + up to 4 conviction items each way); no table |

Sections 9 and 10 are the ones that keep regressing to prose cards. They are TABLES. A
bold headline followed by "Risk:" / "Mitigant:" paragraphs is the wrong format even if
the content is right. Same fields, tabular — not flowing prose, not styled cards.

**Scorecard (section 1):** the Credit Assessment carries a distinct 8-row Scorecard
block (Dimension | tier-translated Rating | Driver), alongside its overall Call and its
lens narratives. This is the current architecture and the scorecard's primary source.
RENDER the 8 rows directly from Credit Assessment dashboard's Scorecard block —
Claude translates rating vocabulary (Above Average / Average / Below Average / Weak) but
does not re-judge or re-derive a dimension's rating. The eight dimensions map one-to-one
onto the memo's fixed eight: Business quality, Cash flow durability, Customer
concentration, Earnings quality, Collateral coverage, Leverage, Management/Sponsor,
Headwinds & Tailwinds. CONFIRMED live on a second reference deal (2026-08-17): the Scorecard block
was present and rendered directly, each row carrying a Rating and a Driver.

Credit Assessment also carries lens narratives and a 9th "Key metrics to watch" lens —
that 9th item is a disclosure lens, NOT one of the memo's eight scorecard dimensions, so
do not render it as a scorecard row. Use the overall Call / summary / repayment read for
the Credit View prose above the scorecard; use the Scorecard block for the eight rows.

FALLBACK ONLY (if the dedicated Scorecard block is genuinely absent on a given deal): do
not mark the scorecard unavailable. Merits & Risks dashboard's own "Snapshot > Assessment" block
also carries a rated 8-dimension assessment (Market position, Industry outlook, Revenue
resilience, Competitive moat, Leverage, EBITDA quality, Cash flow conversion, Debt
